# LawBench 项目技术架构面试短稿

这份文档专门给面试时背诵和快速复述用。

## 1. 30 秒技术架构版

这个项目整体是一个轻量级前后端分离评测系统。前端用 Vue 3 做单页展示，后端用 FastAPI 实现 HTTP API，负责读取 LawBench 官方 JSON、生成 Prompt、调用 DeepSeek、归一化输出并完成自动评测。结果目前先落到本地 JSON 文件，部署层通过 Dockerfile 容器化，最终发布到腾讯云 CloudBase Run，形成公网可访问的演示服务。

## 2. 60 秒技术架构版

这个项目可以拆成五层。第一层是数据层，基于 `open-compass/LawBench` 官方数据，把任务、样本和运行结果抽象成统一结构。第二层是前端展示层，用 Vue 3 把任务目录、数据集设计、样本预览、Prompt 结构和运行结果组织成单页交互界面。第三层是后端服务层，用 FastAPI 实现轻量 HTTP 服务，对外提供任务概览、单条推理、批量评测和历史记录接口。第四层是模型接入层，后端统一调用 DeepSeek API，并对单选题结果做 `A/B/C/D` 归一化，方便自动评分。第五层是部署层，用 Dockerfile 容器化后推到 GitHub，再部署到腾讯云 CloudBase Run，形成公网可访问的演示系统。

## 3. 可扩展性怎么讲

这个项目是有可扩展性的。第一，数据层已经做了任务层、样本层、运行层的抽象，后续接别的 benchmark 也可以复用。第二，模型接入层是统一接口，现在接的是 DeepSeek，后续可以扩展到其他大模型。第三，当前在线自动评测优先支持单选题，后面可以继续扩展到多选题、抽取题和生成题。第四，存储层现在用的是文件型记录，后续可以升级到对象存储或数据库，解决历史记录持久化问题。第五，部署层目前是单容器演示版，后面可以继续拆成前端静态站、后端 API 服务和异步评测任务。

## 4. 项目难点怎么讲

这个项目的难点不只是接模型 API，而是把 benchmark 数据结构、Prompt 组织、输出归一化、自动评测、页面交互和云端部署整合起来。尤其是 LawBench 本身不是现成产品，而是 benchmark 数据和脚本，所以我需要先把任务信息、样本信息和运行结果抽象出来，才能让前端和后端共用同一套结构。另外，不同任务类型的评测方式差异很大，所以我先优先支持自动评分最稳定的单选题任务，保证在线演示的稳定性。

## 5. 如果面试官追问“正式系统怎么升级”

可以这样回答：

如果往正式系统演进，我会优先做三件事。第一，把当前写在本地文件里的历史记录迁移到对象存储或数据库，解决持久化问题。第二，把批量评测从同步请求改成异步任务，提升并发能力和稳定性。第三，把前端静态资源、后端 API 和模型评测任务进一步拆分，形成更清晰的服务边界。

## 6. 最短背诵版

这个项目的架构是 Vue 3 单页展示加 FastAPI 后端，再加 DeepSeek 模型调用和 Docker 云端部署。它的可扩展性主要体现在数据结构分层、模型接口可替换、评测任务可扩展、存储层可升级、部署形态可继续拆分。
